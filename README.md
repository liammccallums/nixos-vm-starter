# NixOS VM starter

A small, declarative **NixOS 26.05** virtual machine for learning NixOS without replacing Fedora. This is an **x86_64-linux / QEMU** VM built straight from a Nix flake. No installation ISO or manual partitioning is needed.

## What's inside

- `flake.nix` selects Nixpkgs and defines the VM configuration.
- `configuration.nix` declares a normal user, packages, Nginx, and VM resources.
- `flake.lock` will be generated by `nix flake lock`. **Commit this file** so the next build uses the same Nixpkgs revision.
- `.gitignore` keeps build output and the VM's mutable disk out of Git.

The VM has 2 vCPUs, 2 GiB RAM, and a text console. It includes Git, Neovim, Python, curl, htop, and an Nginx HTTP endpoint.

## 1. Install Nix on Fedora

These commands install system software on your **Fedora host**. They do not replace Fedora:

```bash
sudo dnf install nix nix-daemon git
sudo systemctl enable --now nix-daemon
nix --version
```

Enable the Nix CLI/flake features for this shell (some Fedora builds already enable them):

```bash
export NIX_CONFIG='experimental-features = nix-command flakes'
```

You also need hardware virtualisation (KVM). If `/dev/kvm` is inaccessible to your user, check its permissions (`ls -l /dev/kvm`) and your group's membership (`id`). You may need to join the host's `kvm` group and log in again.

## 2. Initialise this repo and lock dependencies

From inside the extracted `nixos-vm-starter` directory:

```bash
git init
git add flake.nix configuration.nix .gitignore README.md
nix flake lock
git add flake.lock
```

If you started from an existing clone, skip `git init`. Git must know about the files used by a local flake; merely placing an untracked `configuration.nix` in the directory isn't enough.

## 3. Build the VM (on Fedora)

```bash
nix build '.#nixosConfigurations.vm.config.system.build.vm'
```

This fetches or builds the NixOS system and produces a `result` symlink with its QEMU launcher. The first build downloads a substantial amount of data.

## 4. Run the VM in your terminal

```bash
QEMU_KERNEL_PARAMS='console=ttyS0' \
QEMU_NET_OPTS='hostfwd=tcp:127.0.0.1:8080-:80' \
./result/bin/run-nixos-lab-vm -nographic
```

Sign in at the console:

- Username: `student`
- Password: `test`

**Security:** This intentionally weak password is ONLY for a throwaway local VM. It must not be reused in real deployments. There is no SSH service enabled here; QEMU forwards only localhost port 8080 to Nginx inside the guest.

## 5. Test Nginx from Fedora

In a **second Fedora terminal**, while the VM is running:

```bash
curl http://127.0.0.1:8080
```

Expected:

```text
Hello from NixOS VM!
```

From the **VM terminal**, you can verify services and packages:

```bash
systemctl status nginx
python3 --version
nvim --version
hostname
```

Shut down the guest cleanly with `sudo poweroff`.

## 6. Push to GitHub

Create an **empty** GitHub repository called `nixos-vm-starter`, then from this folder:

```bash
git add .
git commit -m "Initial reproducible NixOS VM"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/nixos-vm-starter.git
git push -u origin main
```

Replace `YOUR_USERNAME` with your GitHub username. GitHub authentication/credentials must already be configured. If cloning a repo with an existing remote, do not add that remote twice.

## 7. Make a change

Edit `configuration.nix`; e.g. add `tree` to `environment.systemPackages` or change the Nginx greeting. Then:

```bash
git add configuration.nix
nix build '.#nixosConfigurations.vm.config.system.build.vm'
```

Shut down the old VM before starting the newly built VM using the command from step 4. If previously initialised files inside the guest prevent the new configuration from taking effect, remove its **local throwaway** `nixos-lab.qcow2` file after shutdown. **This permanently deletes the VM's saved mutable state.** It does not delete your flake/repo or Fedora files.

To update pinned packages later:

```bash
nix flake update
git add flake.lock
git commit -m "Update pinned Nixpkgs revision"
```

## Notes

- This is a **QEMU VM build**, not a complete installer for a physical computer or a normal UEFI/BIOS VM disk.
- It doesn't need `hardware-configuration.nix`, a bootloader, or manual partitioning because the NixOS `system.build.vm` target supplies VM-specific boot and hardware settings.
- Your Git-tracked Nix source and lock file are reproducible inputs; mutable VM data (`*.qcow2`) is deliberately not part of the reproducible configuration.
- First build and later VM launches depend on a usable `/nix` store, virtualization support, and QEMU availability (QEMU is supplied through the Nix VM build).

References: <https://nix.dev/tutorials/nixos/nixos-configuration-on-vm.html> and <https://nixos.org/manual/nixos/stable/>.
